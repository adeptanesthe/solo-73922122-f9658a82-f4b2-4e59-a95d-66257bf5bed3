# 剪辑接缝跳听台（Clip Lab）

给剪辑师剪掉访谈停顿后按**成片时码**跳听接缝的网页工具。Flask + NumPy 实现，
上传单声道 PCM16 WAV，按 **4096 样点**分块，可撤下/恢复任意块；输入成片 0 基
样点号，显示对应原块与块内偏移，并返回从该处到块末的 PCM16 WAV 试听。

## 两窗口改剪的“跳听漂移”问题与修法

同一段访谈开两个窗口时，窗口 A 定位好的成片样点，会被窗口 B 的撤块/恢复改变
映射：同样的样点号可能落到别的原块，入块滤波状态也随保留块集合变化。旧实现
试听链接只带样点号、每次按**当前**剪法实时重算，于是另一窗口改剪后，页面上的
原块/偏移和播放器声音都会漂走。

修法是把**定位与取声解耦**，引入不可变的定位快照
（:class:`~app.engine.AuditionSnapshot`）：

1. **定位** `GET /api/p/<pid>/audition?k=...` 只访问两棵摘要树（原始块读取
   0 次），把定位当时的原块号、块内偏移、入块滤波状态、成片长度冻结成快照，
   用进程内密钥签进一个**无状态令牌**，随固定试听链接
   `/api/p/<pid>/audition.signed.wav/<token>` 下发；
2. **取声/重播** 凭令牌验签后，按快照里的块号只读那一个原始块，从快照里的
   入块状态递推到块末。原始 PCM 不可变，因此撤块/恢复（哪怕命中块本身被撤过
   又恢复）后，同一链接首次加载与重播字节完全一致；
3. 服务端不保存任何逐链接数据（无音频缓存、无快照表），留存数据量不随已发
   链接数增长；DATA_DIR 下始终只有每工程一份 `input.pcm`；
4. 旧入口 `GET /api/p/<pid>/audition.wav?k=...`（只传样点号）保留原语义：
   每次都对**当前成片**实时定位试听。

页面侧定位卡片独立于分块网格保存（`pinned`），撤块/恢复只刷新网格，已定位的
原块、偏移和固定链接保持定位当时的剪法，直到重新点击“定位并试听”。

## 它解决什么问题

剪完之后，低通滤波必须作用在“保留样点拼接后的序列”上，而不是在原时间轴上
滤波后再删块（两种结果不同）。本工具把每块对一阶低通的作用预先做成摘要，
撤块时只改摘要，跳听时用摘要恢复滤波器状态，再只读命中块的原始样点。

### 两个树，两个 O(log N)

一阶低通 `y[n] = a·y[n−1] + (1−a)·x[n]`（零状态起步，全程 float64 不取整）
对一块长度 L 的样点，等价于关于入块状态的仿射变换：

```
y_out = w·y_in + b,  w = a^L,  b = (1−a)·Σ a^(L−1−n)·x[n]
```

| 结构 | 存什么 | 用途 |
|---|---|---|
| Fenwick 计数树 | 每块保留样点数（撤下=0） | 成片样点号 → 原块/块内偏移（前缀和 + 第 k 个位置） |
| 仿射线段树 | 每块 (w,b)；撤下块放恒等 (1,0) | 前缀复合得到“进入某块前”的滤波器状态 |

- **撤下/恢复一块**：Fenwick 单点增减 + 线段树换叶子并向上重算，只碰 O(log N)
  个摘要，原始样点读取 0 次（页面会实时显示这两个计数）。
- **定位**：Fenwick 定位块号/偏移 + 线段树前缀查询入块状态，均为 O(log N)
  摘要，原始块读取 0 次，并冻结为签名快照。
- **取声（含重播）**：按快照只读 **1 个命中原始块**，从入块状态逐样点递推到
  块末，量化输出 PCM16 WAV。定位 + 首次取声合计只读 1 个原始块。

## 目录

```
app/engine.py      Fenwick 树、仿射线段树、Project（分块/撤恢复/定位/跳听）

app/main.py        Flask 路由（上传、撤/恢复、状态、跳听 JSON/WAV）

```

## 启动（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:5000
```

容器单 gunicorn worker + 多线程（工程状态在进程内存，多 worker 会互不可见），
上传的裸 PCM 落在命名卷 `clip-data`（容器内 `/data`）。

不用 Docker 的本地跑法：

```bash
pip install -r requirements.txt
python tools/make_sample_wav.py sample_audio/interview_demo.wav   # 已附带可跳过
flask --app app.main run
```

## 试用流程

1. 首页选 `sample_audio/interview_demo.wav`，填系数 a（0 ≤ a < 1，如 0.9），上传。
2. 工程页 40 个块按网格展示；红色块即示例里的停顿块（#3、#4、#9、#16、#17、
   #25、#32），点任意块撤下/恢复，下方显示本次访问的摘要数与原始块读取数。
3. 在“成片时码跳听”输入 0 基样点号（页面标注当前有效范围），点定位：
   - 显示原块号、块内偏移、原始录音样点号、试听时长，并标注“已冻结·定位当时
     的剪法”与固定试听链接；
   - 播放器加载从该样点到块末的滤波后 PCM16 WAV；之后在任意窗口撤块/恢复，
     该卡片与链接不变，重播仍是定位当时的声音（工程在则链接一直有效）；
   - 重新点击“定位并试听”才会按当前剪法生成新的快照链接；
   - 越界（负数或 ≥ 保留样点数）返回 400，页面红条提示重新选择。

### 两窗口演示

1. 窗口 A 上传录音，撤下块 #3，对 `k=12288` 定位 → 显示原块 **#4** 偏移 0，
   得到签名试听链接并播放；
2. 窗口 B 恢复块 #3、再撤下并恢复块 #4（模拟连续改剪）；
3. 回到窗口 A 重播同一链接：HTTP 200、WAV 字节与首次完全一致，
   `X-Chunk-Loads: 1`；而对当前剪法重新定位 `k=12288` 已落到原块 **#3**；
4. 旧入口 `audition.wav?k=12288` 返回当前剪法的声音，与新定位一致、与冻结
   链接不同。

## 验证结果

在 Python 3.11 + NumPy 2.4 + Flask 3.1 下执行（命令均在仓库根目录）：

```bash
PYTHONPATH=. python tests/test_core.py     # 引擎断言（含快照冻结），全部通过
PYTHONPATH=. python tests/test_web.py      # Flask 路由，全部通过
PYTHONPATH=. python tests/e2e_http.py      # 起服务后的真实 HTTP 端到端，全部通过
```

关键核对点：

- **量化误差**：随机录音、a ∈ {0, 0.3, 0.85, 0.99}、随机撤块（含非整块结尾），
  对每个保留块块首与块内随机偏移做跳听，与“先拼接保留样点、零状态顺序滤波、
  最后统一量化”的参考实现逐样点比对，最大差 0（题目要求 ≤ 1 个量化单位）。
  两种路径都是 float64 递推、仅在输出时 `rint` 量化，因此结果一致。
- **快照冻结（两窗场景）**：定位后撤下/恢复多个块（含命中块本身被撤再恢复、
  最后全部恢复），同一签名链接每次重放 WAV 字节级不变；快照只含 5 个定长
  标量字段，不持有任何样点；伪造令牌与跨工程令牌均返回 404。
- **读取次数**：定位原始块读取恒为 0、摘要访问为对数级；取声（首次加载或
  重播）只读 1 个命中原始块，响应头 `X-Chunk-Loads: 1`；定位 + 首次取声
  合计 1 次读块。N=16/64/256 块实测撤块/恢复摘要访问 10/14/18 个，随 log N
  增长；HTTP 端到端 40 块工程单次操作摘要访问 ≤ 24。
- **无逐链接留存**：大量发链后 DATA_DIR 仍只有每工程一份 `input.pcm`，
  服务端没有快照表或音频缓存，留存数据不随链接数增长。
- **旧入口兼容**：`audition.wav?k=...` 仍对当前成片实时试听，与同剪法下新
  定位的签名 WAV 完全相同。
- **时码**：枚举全部成片样点号核对定位；越界与非整数输入均 400 并提示重选。
- **格式**：非 WAV、立体声、非 16 位、a 越界/非数字全部拒绝；试听 WAV 为
  单声道 PCM16、同采样率、帧数等于“到块末”样点数。

## 约定与边界

- 上传上限 128 MiB；仅接受单声道、16-bit PCM WAV。
- 工程保存在服务进程内存（重启失效），原始 PCM 落盘在 `/data`；快照签名
  密钥也是进程内随机生成，进程重启后旧链接失效（工程本身也已不在）。
- 末块不足 4096 样点时按实际长度处理，摘要与计数自然兼容。
- a=0 时滤波器退化为直通，已专项测试。

## 余下工作

- 本环境没有 Docker 守护进程（无 `docker` 二进制），**镜像未在此处实际构建/
  运行**；已用与容器相同的 gunicorn 单 worker + 8 线程命令在本地起服务跑通
  全部 HTTP 端到端，Dockerfile 与 compose 未改动，需在有 Docker 的机器上
  `docker compose up --build` 复核一次。
- 工程状态与签名密钥未持久化，服务重启需重新上传、旧链接失效；多副本部署
  需要外置存储与共享密钥。
- 试听固定输出“到块末”，没有跨块连续试听与波形可视化。
- 大文件上传与长录音只有 128 MiB 大小限制，没有分片上传和进度展示。
